SECTION 1
Project Overview & Goals
1. Project Overview
Fiber Jet is a fully self-hosted, full-stack ISP management platform. Every component — API server, database, file storage, real-time engine, and admin panel — runs on your own VPS infrastructure, giving you complete control over data, security, and costs.
The platform serves four distinct user roles through dedicated mobile interfaces (Flutter) and a web admin dashboard (React), all powered by a Laravel 11 REST API backed by PostgreSQL via Supabase and Nextcloud for customer file storage.
1.1 Self-Hosted Infrastructure Philosophy
Zero vendor lock-in — every service can be migrated or scaled independently
100% data sovereignty — all customer data, files, and logs stay on your VPS
Cost efficiency — no per-GB cloud storage fees, no SaaS per-seat charges
Security by design — no third-party company has access to your customer data
Full audit control — every request, file, and database change is logged on your own server

SECTION 2
Supabase + PostgreSQL Architecture
2. Supabase (Self-Hosted) + PostgreSQL
Supabase is deployed self-hosted on your VPS using the official Docker Compose stack. Laravel connects to the PostgreSQL 16 database directly via the standard pg driver. Supabase Studio provides a visual database UI for your team.

2.2 Laravel ↔ PostgreSQL Connection
config/database.php:  
DB_CONNECTION=pgsql | DB_HOST=127.0.0.1 | DB_PORT=5432 | DB_DATABASE=fiberjet | DB_USERNAME=fiberjet_app | DB_PASSWORD=[strong_password] | DB_SSLMODE=require
Security Note:  
The PostgreSQL port 5432 is bound to localhost only. No external network access. Laravel connects via Unix socket or 127.0.0.1. Supabase Studio is accessed via SSH tunnel or private network — never exposed on a public port.
2.3 Row Level Security (RLS) Policies
RLS is enabled on all user-facing tables as a defence-in-depth layer. Even if a bug in the application code attempts to read another user's data, PostgreSQL's RLS policy will block it at the database level.

2.4 PostgreSQL Performance Configuration
Connection pooling: PgBouncer deployed alongside PostgreSQL — Laravel connects via port 6432 (pooler), not 5432 directly
Indexes on all foreign keys, frequently filtered columns (status, role, created_at)
Partial indexes on active records: CREATE INDEX ON user_plans (user_id) WHERE status = 'active'
pg_stat_statements extension enabled — slow queries logged and reviewed weekly
Autovacuum tuned for write-heavy tables (leads, audit_logs, notifications)
Read replicas: optional streaming replication to second VPS for report queries
SECTION 3
Nextcloud — Customer Cloud Drive
3. Nextcloud (Self-Hosted) — Cloud Drive
Nextcloud is deployed self-hosted on your VPS and serves as the Cloud Drive backend for customers. Laravel integrates with Nextcloud via its WebDAV API to provision user accounts, upload/download files, and manage storage quotas — all transparently from within the Fiber Jet mobile app.
3.1 Nextcloud Integration Architecture
Integration Method:  
Laravel communicates with Nextcloud via WebDAV (RFC 4918) and Nextcloud's OCS Provisioning API. Customers never interact with Nextcloud directly — all file operations go through the Fiber Jet API, which proxies to Nextcloud behind the scenes.

Admin account uses a strong random password stored only in Laravel .env
Customer Nextcloud passwords are machine-generated UUIDs — customers never know them (all access via app)

SECTION 4
Database Schema — PostgreSQL 16
4. Database Schema (PostgreSQL)
All tables use PostgreSQL-native types: UUID primary keys (gen_random_uuid()), TIMESTAMPTZ for timestamps, JSONB for flexible data, and TEXT with CHECK constraints. Laravel Eloquent models map to these tables via standard Eloquent conventions.
PostgreSQL over MySQL:  
Using PostgreSQL gives us: UUID primary keys natively, JSONB for flexible config storage, full-text search, Row Level Security, superior ACID compliance, and better performance under high concurrency — all critical for a production ISP platform.

4.2 PostgreSQL-Specific Features Used
UUID primary keys: DEFAULT gen_random_uuid() — no sequential ID guessing attacks
MACADDR type for network_devices — PostgreSQL validates MAC address format at DB level
INET type for IP addresses — validates IPv4/IPv6 format natively
JSONB for checklist, ott_benefits, data columns — indexable JSON storage
POINT type for user location — enables geospatial distance queries
TEXT[] (array) for ads.target_roles — native array type, no join table needed
TIMESTAMPTZ everywhere — timezone-aware timestamps prevent DST bugs
CHECK constraints inline — stars BETWEEN 1 AND 5, role IN ('customer','sales','technician','admin')
pgcrypto for OTP hashing: INSERT otp_hash = crypt(otp_code, gen_salt('bf', 12))
pg_cron: scheduled job to DELETE FROM otp_logs WHERE expires_at < NOW() — runs every 5 minutes
SECTION 5
Security Architecture — Multi-Layer Defence
5. Security Architecture
Security is implemented as independent, overlapping layers. A failure at any one layer does not compromise the system because each subsequent layer independently enforces its own controls. This is the zero-trust, defence-in-depth model.
5.1 Authentication Security
OTP: 6-digit, valid 5 minutes, stored as bcrypt hash (never plain text)
Rate limiting: max 3 OTP requests per phone number per 15 minutes (enforced via Redis)
Account lockout: 5 consecutive failed OTP attempts → 30 minute lockout, admin notified
Laravel Sanctum Bearer tokens — per-device, hashed in DB, plain token issued once
Token TTL: 24h for customers, 8h for admin/sales/technician
Tokens stored in Flutter Secure Storage (iOS Keychain / Android Keystore) — never in plain SharedPreferences
New device login → push notification alert sent to user immediately
Admin/Sales/Technician accounts require manual admin approval before first login
5.2 API Security
All traffic over HTTPS — HTTP requests redirected at Nginx, rejected if bypass attempted
TLS 1.3 only — TLS 1.0 and 1.1 explicitly disabled in Nginx SSL config
HSTS: Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
Rate limiting: 60 req/min per token (customer), 200 req/min (admin) — Redis-backed
CORS: only registered Flutter app bundle IDs and admin domain allowed
All input validated via Laravel Form Request classes before any controller logic runs
Eloquent ORM only — no raw SQL queries permitted in codebase (enforced by code review)
Security headers on every response: X-Content-Type-Options: nosniff, X-Frame-Options: DENY, Referrer-Policy: no-referrer
Laravel SQL query log enabled in staging — reviewed for any unparameterized queries
5.3 Data Encryption
Data
Encryption Method
Passwords
bcrypt cost 12 — Laravel Hash::make() — never stored plain
OTP codes
bcrypt via pgcrypto crypt() — stored as hash, compared with crypt()
Aadhaar / PAN
AES-256-GCM via Laravel Crypt::encryptString() — encrypted before INSERT

Password-protected + TLS tunnel if Redis on separate host
5.4 Nextcloud-Specific Security
Nextcloud admin password: 64-char random string stored only in Laravel .env — not in any database or code
Customer Nextcloud passwords: machine-generated UUID — customer can never log into Nextcloud directly
All Nextcloud WebDAV calls use HTTPS — Nginx terminates SSL, Nextcloud served on internal port
Share links for downloads: expire after 15 minutes — enforced at Nextcloud API level
ClamAV antivirus: scans every uploaded file before it is stored — infected files rejected with error
Nextcloud file access logs: every operation (upload, download, delete, share) logged with user ID and timestamp
Emergency lockdown: ./occ maintenance:mode --on — freezes all Nextcloud file access in seconds
5.5 PostgreSQL / Supabase Security
Port 5432: bound to 127.0.0.1 only — zero external access, confirmed via ufw and netstat
Supabase Studio: accessed via SSH tunnel only — no public port exposed
Application DB user (fiberjet_app): GRANT only SELECT, INSERT, UPDATE, DELETE — no DROP, TRUNCATE, CREATE
Migration user (fiberjet_migrate): separate user with CREATE/ALTER permissions — used only during deployments
Row Level Security enforced on all user-facing tables — documented in Section 2.3
pg_audit extension: logs all DDL and sensitive DML operations
Connection limit per user: fiberjet_app limited to 20 connections — prevents connection exhaustion DoS
SSL required: pg_hba.conf: hostssl all fiberjet_app 127.0.0.1/32 scram-sha-256
5.6 Mobile App Security (Flutter)
Certificate pinning: Flutter app rejects connections with untrusted certificates (MITM prevention)
Root/jailbreak detection: FlutterJailbreak package — warns user, restricts file access on compromised devices
Biometric auth: fingerprint / Face ID option for app unlock (LocalAuthentication package)
Flutter Secure Storage: all tokens in iOS Keychain / Android Keystore — not SharedPreferences
Screenshot/screen recording prevention on: Cloud Drive, Plans (billing), Profile (personal data)
ProGuard + obfuscation: enabled on Android release builds — prevents APK reverse engineering
No sensitive data in logs: flutter_lints rule enforced, Logger stripped in production builds
Minimum OS: iOS 14+ / Android 8+ — older OS versions have known unpatched vulnerabilities
5.7 VPS Infrastructure Security
OS: Ubuntu 22.04 LTS — unattended-upgrades enabled for automatic security patches
Firewall (UFW): ONLY ports 22 (SSH), 80 (HTTP redirect), 443 (HTTPS) open — all else denied
SSH: key-based authentication only — PasswordAuthentication no in /etc/ssh/sshd_config
SSH port: changed from 22 to custom port — reduces automated scan exposure
Fail2ban: bans IPs with 5+ failed SSH or API auth attempts for 1 hour
Nginx: server_tokens off — Nginx version not disclosed in response headers
Redis: requirepass set, bind 127.0.0.1, no external port
Nextcloud: served on internal port (e.g., 8080), Nginx reverse proxy handles public HTTPS
Supabase Docker stack: internal Docker network only — no container ports mapped to 0.0.0.0
Intrusion detection: OSSEC or Wazuh — monitors file integrity and system calls
Log aggregation: all Nginx, Laravel, PostgreSQL, Nextcloud logs centralised via Filebeat
Backup: daily pg_dump + Nextcloud data dir snapshot — encrypted with GPG, stored on separate backup VPS

9. Deployment Architecture
All services run on your own VPS infrastructure. The recommended setup uses Docker Compose for Supabase/PostgreSQL and Soketi, with Nginx as the reverse proxy for all services. Laravel runs natively on PHP-FPM for maximum performance.

9.3 CI/CD Pipeline
Developer pushes to feature branch on GitHub
GitHub Actions: runs PHPUnit tests + Flutter tests
Code review: minimum 1 approver required before merge to main
Merge to main: GitHub Actions SSH deploys to VPS
Deploy script: git pull, composer install --no-dev, php artisan migrate, php artisan config:cache
Queue workers restarted: php artisan queue:restart (zero-downtime — Supervisor respawns)
Health check: curl api.yourdomain.com/api/v1/health — must return 200 within 5 seconds
Deployment marked success — Slack/email notification sent
9.4 Backup Strategy
PostgreSQL: daily pg_dump at 02:00 UTC → GPG encrypted → rclone to backup VPS
Nextcloud data: daily rsync of Nextcloud data directory → encrypted → backup VPS
Laravel .env: manually backed up to password manager — never in Git
Retention: daily backups kept for 30 days, weekly for 3 months, monthly for 1 year
Restore tested monthly on a staging environment — untested backups are not backups
SECTION 10
Key Feature Specifications
10. Key Feature Specifications
10.1 Customer Cloud Drive (Nextcloud)
On customer registration: Laravel calls Nextcloud OCS API to create a user account + set initial quota based on plan
Upload flow: Flutter picks file → sends to Laravel API → Laravel streams to Nextcloud WebDAV → returns file record stored in PostgreSQL cloud_files table
Download flow: Laravel calls Nextcloud share API → gets temporary URL (15 min) → returns to Flutter app
Plan upgrade: Laravel updates Nextcloud quota via OCS API immediately upon plan approval
VIP flag: sets Nextcloud quota to 100GB regardless of plan
Expired plan: Laravel sets Nextcloud user to read-only mode via OCS quota limit
10.2 Network Scanner
Fetches connected devices via SNMP v2c or TR-069 protocol from customer's ONT/router
Data returned: device name, MAC address (MACADDR type in PostgreSQL), IP address, connection type, last seen
Trust: adds MAC to trusted list, removes from alert threshold count
Block: sends SNMP SET command to router to blacklist MAC address
Auto-scan: scheduled via Laravel queue job every 30 minutes per active user
Alert rule: 3 or more unknown (untrusted, unblocked) devices → FCM push + red banner + create notification record in PostgreSQL
10.3 Speed Test
Uses iPerf3 against your self-hosted iPerf3 server or Cloudflare Speed Test API
Results: download speed (Mbps), upload speed (Mbps), ping (ms), jitter (ms)
Saved to speed_tests table in PostgreSQL with timestamp and user_id
Comparison: result vs plan guaranteed speed — if below 80% of plan speed, push notification sent
Historical chart: last 30 results shown as line graph in Flutter app
10.4 Leads Pipeline (Sales)
Stages: New → Contacted → KYC Uploaded → Approved → Installed → Churned
Lead score: Hot (contacted < 24h, KYC ready), Warm (follow-up due), Cold (no response 7+ days) — auto-calculated
KYC documents uploaded to Nextcloud under /Sales/KYC/{lead_id}/ folder — path saved in leads.kyc_doc_path
Commission preview: calculated and shown when lead reaches Approved stage
Monthly target ring: progress bar on dashboard showing MTD closed leads vs target
Follow-up reminder: FCM push sent at scheduled follow_up_at timestamp via Laravel queue
10.5 Technician Job Workflow
States: Assigned → En Route → Arrived → In Progress → Completed / Rejected
Mandatory checklist stored as JSONB: install ONT, configure router, run speed test, upload photos
Photo proof: minimum 1 before + 1 after photo required — uploaded to Nextcloud /Jobs/{job_id}/
ETA notification: when technician taps En Route, customer receives push with estimated time
Offline mode: job details cached in device SQLite via Hive package, synced when connectivity restored
Rejection: reason + photo + comment saved — admin receives immediate FCM push
10.6 VIP / Permanent User
Admin sets is_vip = true on the user record
Immediate effects: Nextcloud quota upgraded to 100GB, priority support queue flag set, golden badge shown in app
Support tickets: auto-set to priority status — sorted to top of admin queue
Self-service tasks: can upload photos for minor issues, reducing technician visit requirement
